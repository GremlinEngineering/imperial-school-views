# Android 1.3.3: сверка с Mac и действующим сервером

Дата: 31 октября 2026. Проверенная база: Android 1.3.2, Mac 1.8.8, сохранённый CLIENT_API_1.7.0.md с уточнениями 1.7.2, серверный Gremlin_Build_Incremental_1.0.24_files.zip. Проверка касается API, доставки, кеша, погодных правил и интерфейса этих функций; нативные компоненты Mac не являются требованиями Android.

## Найдено и исправлено

| Участок | Android 1.3.2 | Android 1.3.3 |
| --- | --- | --- |
| HTTP-сжатие JSON | HttpURLConnection мог автоматически распаковать gzip на Android; явной поддержки Brotli не было | JSON явно запрашивает br/gzip и распаковывается общим декодером |
| Прямой адрес .json.br | Строгая проверка current/forecast разрешала только .json | Допустимы точные ожидаемые .json и .json.br; чужой хост/путь не разрешён |
| Распаковка | Для Brotli не реализована | Заголовок Content-Encoding учитывается; прямой .json.br без заголовка распаковывается; br не декодируется дважды |
| Ограничение размера | Ограничение прочитанных байтов | Ограничены как сжатые, так и распакованные байты; повреждённое/неизвестное сжатие даёт понятную ошибку |
| Обновление прогноза | current записывался до окончания загрузки forecast | При неизменной идентичности отказ оставляет прежнюю совместимую пару; записывается только согласованная новая пара |
| Новая игра / локация | Старый прогноз сохранялся внутри частично обновлённой пары | Подтверждённое изменение идентичности сразу исключает старое покрытие, даже если forecast затем не загрузился |
| Повреждённый кеш прогноза | Ошибка разбора могла прерывать обновление до сетевого запроса | Кеш считается отсутствующим; запрашивается новая пара |
| Явный формат | Исчезнувший формат мог заменяться phone/первым доступным | Явный недоступный формат выдаёт ошибку; автоматический выбор остаётся только для auto |
| Местоположение Open-Meteo | Ручной выбор города | Ручной выбор и определение координат Android по кнопке |

Общий декодер применяется к manifest-v3, current, forecast, android-release, поиску города и прогнозу Open-Meteo. ZIP/JPEG не переводятся через декодер JSON: контрольные суммы проверяют исходные байты.

Сервер 1.0.24 создаёт .br как дополнительную производную от исходного JSON; при ошибке сжатия исходный JSON продолжает публиковаться. Поэтому корневые запросы остаются к .json с Accept-Encoding, без механической замены всех URL на .br. Адрес .json.br из погодного каталога также поддержан. В Mac 1.8.8 для сетевых JSON используется curl --compressed.

## Что совпадает и какие отличия остались

| Возможность | Результат сверки |
| --- | --- |
| manifest-v3, schema 3, игнорирование дополнительных полей | Сохранено; текущий каталог с ultrawide разбирается |
| real / game-world | Сохранено; Москва не появляется в пользовательской подписи серверной погоды |
| current + forecast, world_id / location_revision / timezone, интервалы [from,until) | Совместимость проверяется; обновление пары исправлено |
| Последний кадр, истечение покрытия, локальные границы интервалов | Сохранены прежние проверки и таймеры Android |
| Open-Meteo, астрономия, таблица WMO, восемь фаз Луны | astronomy.js, weather-policy.js и open-meteo.js побайтово совпадают с Mac 1.8.8 |
| Часовой пояс / DST | Для города берётся зона результата поиска; для координат — timezone=auto Open-Meteo; локальные расчёты используют IANA-зону |
| ZIP: отдельные версии устройства, SHA-256, переиспользование | Сохранено. Внешнее поле bytes не является причиной отказа при совпавшем SHA-256; проверки JPEG внутри пакета сохранены |
| Выбор сети и прогресс ZIP | Сохранены «Только Wi-Fi» и «Wi-Fi и мобильная сеть», этапы, процент, байты и закреплённый статус |
| Отдельные профили экранов | Для Android — главный экран и блокировка; местоположение независимо сохраняется в каждом профиле |
| Горизонтальные форматы / ultrawide | Android выбирает вертикальные форматы; desktop-only коллекции скрыты. Elevator Action на момент проверки не публиковал phone |
| Обычные «Обои дня» | Существуют; следуют wallpaper_of_day каталога |
| Погодная «Погода дня» | **Отсутствует в Android**, присутствует в Mac. Это отдельный источник выбора коллекции сервером через weather/daily/<source>/current.json, а не обычные «Обои дня». В этом выпуске режим не добавлялся |
| Mac LaunchAgent / хранитель экрана / мониторы | Платформенные функции; Android использует WorkManager, AlarmManager и два профиля обоев |

## Геолокация

Путь: «Погодные обои» → коллекция с phone → «Open-Meteo · город / геолокация» → «Выбрать город вручную…» или «Моё местоположение…» → «Применить».

Android запрашивает foreground coarse/fine-разрешения только по нажатию. Приблизительного разрешения достаточно. Используются доступные провайдеры LocationManager; принимается свежая отметка не старше 10 минут с точностью до 25 км либо новый результат. Ожидание ограничено 25 секундами. Подписки удаляются при успехе, таймауте, отмене и уходе из окна. ACCESS_BACKGROUND_LOCATION не запрашивается.

По координатам запрашивается timezone=auto. В профиль записываются исходные координаты телефона, а не координаты ячейки погодной модели, возвращённые API. Город и GPS используют общий погодный/астрономический механизм. ZIP не зависит от местоположения и повторно ради него не загружается. Для нового места пользователь нажимает «Обновить моё местоположение…»; автоматического слежения за поездкой нет. При отказе или ошибке прежнее место и системные обои не заменяются.

## Проверки

89 тестов JVM/Robolectric: 66 прежних, 10 сценариев JSON/Brotli/gzip, 5 сценариев обновления пары, 7 сценариев геолокации и один дополнительный тест интерфейса. Ошибок и пропусков нет. Проверены повреждение сжатых данных, лимиты после распаковки, прямой .br, комбинации заголовков, чужие адреса, отказ обновления, новая локация, приблизительное разрешение, отмена/таймаут, отказ разрешения, отсутствие фонового разрешения, независимость профилей. Рендер интерфейса проверен в светлой теме 360 dp и тёмной 320 dp со шрифтом 150%, включая обе кнопки местоположения.

Сделана подписанная release-сборка, apksigner verify и zipalign прошли. Сертификат SHA-256: 69d0f5e426d31a438f82ef33f2339bd4ede8e682313405615589ac185b7146a8, прежний applicationId; versionName 1.3.3, versionCode 8, Android 8+.

Живые запросы: каталог отвечает Brotli (23 483 байта вместо 97 806), прямой manifest-v3.json.br — те же распакованные байты; current/forecast двух погодных коллекций отвечают gzip. Оба daily-источника существуют на сайте. Подробности: api-audit/live-http.json. Open-Meteo по координатам Берлина с timezone=auto вернул Europe/Berlin. Эти HTTP-проверки выполнены отдельно от Android; тесты декодера и экранов — JVM/Robolectric.

На момент проверки android-release.json сайта всё ещё рекламировал Android 1.3.0/build 5. Выданный пакет сам по себе не меняет опубликованные файлы сайта.

Физический телефон и эмулятор не запускались. Получение GPS и ограничения конкретного устройства требуют проверки на телефоне. Тестовые изображения интерфейса отражают подготовленные состояния Robolectric, не живую GPS-сессию. Большие ZIP не скачивались повторно: их формат и проверка в 1.3.3 не изменены; прежние отчёты сохранены с исходными версиями.

Источники API: https://open-meteo.com/en/docs ; https://developer.android.com/develop/sensors-and-location/location/permissions/runtime ; https://developer.android.com/reference/java/net/HttpURLConnection .
