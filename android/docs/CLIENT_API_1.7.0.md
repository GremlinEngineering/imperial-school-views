# Погодные обои: API для клиентов 1.7.0

Контракт опубликованных файлов сервера Imperial School Weather 1.7.0–1.7.2. Документация сверена с `gremlin_weather.py`, `gremlin_weather_fantasy.py`, `gremlin_views.py` и `weather-client.js` из обновления 1.7.0. Исправление 1.7.2 сохраняет этот публичный контракт; наличие файлов на работающем сайте зависит от завершения сборки и публикации.

API предназначен для клиентов macOS, Windows, Android и других приложений, которые устанавливают обои по погоде. Сервер публикует JSON и готовые JPEG. Клиент выбирает источник и размер, загружает прогноз и переключает изображения по своему таймеру.


## Изменения относительно 1.6

- JPEG: постоянные пути `collections/C/files/<state>[-<moon-phase>]-D.jpg`, например `autumn-day-clear-macbook.jpg` или `autumn-night-clear-full-moon-phone.jpg`. Фазы в именах записываются через дефис, в JSON — через подчёркивание.
- Превью: `collections/C/previews/<тот-же-stem>-thumbnail.jpg` и `-player.jpg`.
- ZIP: постоянный путь `downloads/weather-C-D.zip`; новая независимая версия каждого устройства находится в `forecast.package_version`, `collection.package_versions[D]` и записи скачивания `version`.
- Байты по постоянному URL могут обновиться. Кешировать по `sha256`, а не только по URL. Для HTTP-загрузки можно добавлять `?v=<sha256>`; это не отдельная версия файла на сервере. Веб-плеер добавляет этот параметр.
- Если сохранённый прогноз ожидает старый SHA-256, а URL уже отдаёт новые байты, обновить текущий JSON и прогноз. Не устанавливать файл с несовпавшей контрольной суммой. Старые копии на 48 часов не сохраняются.
- При переходе с 1.6 старые хешированные ссылки удаляются после успешной полной сборки. Клиенту с сохранёнными старыми JSON нужно заново загрузить каталог и прогноз.
- В `location` игрового источника используются координаты Luna. Часовой пояс остаётся серверной настройкой; в приложенном конфиге — `Europe/Moscow`. У ранее созданного профиля без координат сохраняются прежние координаты конфигурации до явного `--regenerate`.
- Сайт начинает с `game-world`. Реальный источник API сохранён. Один день мира по-прежнему равен одному реальному дню.

## 1. Адрес и версии

Базовый адрес:

```text
https://games.oopssre.ru/assets/arcade/views/
```

Все относительные пути из JSON разрешаются **от этого адреса**, включая пути внутри вложенного `current.json` или `forecast-*.json`:

```js
const BASE = new URL('https://games.oopssre.ru/assets/arcade/views/');
const absolute = new URL(file.url, BASE);
```

Не разрешать `collections/...` относительно адреса самого прогноза.

| Документ | Поле версии | Значение |
| --- | --- | --- |
| Общий каталог `manifest-v3.json` | `schema` | `3` |
| Текущее состояние `current.json` | `schema` | `1` |
| Прогноз `forecast-<device>.json` | `schema` | `1` |
| Каталог подготовленных кадров `assets.json` | `schema` | `1` |
| `manifest.json` внутри погодного ZIP | `schema` | `3` |

`1.7.0` — версия серверного модуля. Это не значение `schema`. Внутренняя ревизия прогноза `6` не публикуется отдельным полем. `contract_version` и версия коллекции — непрозрачные строки, их нельзя сравнивать как semver.

Старый общий `manifest.json` со `schema: 2` не включает погодные коллекции. Новый клиент начинает с `manifest-v3.json` и отбирает `collections` с `type: "weather"`. В этом же каталоге могут оставаться обычные коллекции.

## 2. Запросы

Достаточно HTTP GET. В серверном модуле нет авторизации, пользовательских параметров запроса, POST, WebSocket или endpoint для вызова Luna. Параметры города, календаря и активной игры задаёт сервер. HTTP-заголовки кеширования и CORS определяет веб-сервер; этот модуль их не настраивает. Для браузерного клиента на другом домене CORS нужно проверить отдельно.

Обозначения: `C` — ID оформления, `D` — ключ формата из `formats`. Например, `C = metal-slug-x-weather`, `D = macbook`.

| Ресурс | Путь от базового адреса |
| --- | --- |
| Каталог коллекций и ZIP | `manifest-v3.json` |
| Текущее состояние реальной погоды | `weather/C/current.json` |
| Прогноз реальной погоды для формата D | `weather/C/forecast-D.json` |
| Текущее состояние игрового мира | `weather/C/sources/game-world/current.json` |
| Прогноз игрового мира для формата D | `weather/C/sources/game-world/forecast-D.json` |
| Все подготовленные кадры оформления | `weather/C/assets.json` |
| Постоянный JPEG реальной погоды | `weather/C/current-D.jpg` |
| Постоянный JPEG игрового мира | `weather/C/sources/game-world/current-D.jpg` |
| Постоянное малое превью | `weather/C/current-preview.jpg` или `weather/C/sources/game-world/current-preview.jpg` |

Для реальной погоды нет обязательного пути `/sources/real/`. Для игрового мира используется ровно `game-world`. Источник не называется `metal-slug`, даже если такое имя есть у оформления.

Постоянные JPEG существуют только при `delivery.direct_image.enabled: true` и после успешной подготовки соответствующего кадра. Они обновляются при запуске серверного обновления. Для точной смены обоев между этими запусками использовать прогноз и `interval.file.url`.

## 3. Источник погоды и оформление

Это два независимых выбора:

- `collection_id` задаёт набор рисунков, например Metal Slug X.
- `source_id` задаёт погоду: `real` или `game-world`.
- `world_id` задаёт активную игру, например `ra-12026`. У `real` значение `null`.

Поэтому рисунки Metal Slug могут отображать погоду мира другой игры. Название активного мира брать из `current.source.name`, сведения об игре — из `current.source.game`. Основную подпись окружения брать из `source.setting`, с запасным вариантом `source.name`. `collection.title` — название оформления.

Игру выбирает сервер детерминированно по игровому профилю. Luna одним ответом задаёт климат, начальный сезон, год начала мира (`world_year`) и координаты окружения (`coordinates`) выбранной игры; профиль, начало календаря и seed сохраняются. Реальный месяц не определяет стартовый сезон. Мир начинает первый день выбранного сезона в выбранном моделью году, затем его календарь идёт по одному дню за реальный день. Далее Fantasy Calendar рассчитывает погодный код на каждую местную дату. В пределах `world_date` код одинаков, но освещение и изображение меняются на границах рассвета, дня, заката и ночи. Чтение API не вызывает GPT.

Год мира берётся из сюжетных сведений об игре. Если климат следующей игры получить не удалось, сервер продолжает публиковать прежний активный мир. До первого готового климата игровой источник недоступен. Публичный API сообщает активный мир; состояние кандидатов на его замену не публикуется.

### Календарь мира в 1.7.0

В `source.calendar` нового профиля передаются `initial_season`, `origin_date` (реальная дата создания календаря в часовом поясе мира), `world_start_date` (дата первого дня выбранного сезона). `initial_season` — исходный выбор Luna; текущий сезон брать из интервала, поскольку время мира продолжает идти. Например, при выборе `summer` и `world_year: 2031` дата мира начинается с 1 июня 2031 года, независимо от реального года. Световой день и фаза Луны также соответствуют дате мира. `astronomy.days` по-прежнему индексируется реальными местными датами, а события имеют реальные метки времени для клиентских таймеров.

Клиент не вызывает модель и не меняет стартовый сезон. Для намеренной перегенерации владелец запускает серверную команду `gremlin_weather_world.py --regenerate`; отдельного HTTP endpoint нет. Старые готовые профили до этой команды могут не иметь `calendar` и продолжать прежний календарь. Автоматической платной миграции нет. `source.date_offset_days` при новом календаре — вычисленная служебная величина, а не настройка, которую нужно вводить пользователю.

### Общая картина недоступности в 1.7.0

В корневом `manifest-v3.json.weather_fallback` есть метаданные общей иллюстрации: `url: "weather-unavailable.png"`, `format: "png"`, `width`, `height`, `bytes`, `sha256`. Это отдельная картина катастрофы для недоступных данных или рисунков. Она не является `interval.file`, не меняет статус прогноза и не подчиняется размерам конкретного устройства. В приложении её можно вписать в экран по собственным правилам, сохранив пропорции. Проверять её по этим метаданным, а не функцией проверки JPEG погодного кадра.

Сайт при неготовом выбранном формате, просроченном/отсутствующем прогнозе и ошибке загрузки картинки показывает эту иллюстрацию. Старый осенний рисунок больше не показывается как замена летнего. Метаданные `last_successful_image` сохранены в API для совместимости, но это прежний кадр. Ещё действующий совместимый прогноз можно продолжать использовать при сетевом сбое; после его истечения не продлевать срок.

Основная подпись — `source.setting` с запасным вариантом `source.name`. Дату под постером форматировать из текущего `world_date`, включая уже выбранный моделью год; например `2031-06-01` → «1 июня 2031». В интерфейсе текущий сезон брать из интервала, не из месяца устройства и не из первоначального `initial_season`. Сайт скрывает дату просроченного прогноза. Старые профили без нового `world_year` сохраняют свой календарь до явного серверного `--regenerate`; клиенту для этого не нужен отдельный запрос модели.

## 4. Каталог `manifest-v3.json`

Ниже сокращённая иллюстрация структуры, а не снимок текущего сервера. Размеры и количество готовых состояний читать из ответа.

```json
{
  "schema": 3,
  "collections": [
    {
      "id": "metal-slug-x-weather",
      "type": "weather",
      "title": "Metal Slug X · Погода",
      "version": "discovery-0123456789abcdef",
      "current_url": "weather/metal-slug-x-weather/current.json",
      "formats": {
        "macbook": {"width": 3840, "height": 2400, "aspect": "16:10"}
      },
      "ready_states": 52,
      "total_states": 208,
      "capabilities": ["weather", "current-image"],
      "sources": [
        {
          "id": "real",
          "title": "Реальная погода",
          "current_url": "weather/metal-slug-x-weather/current.json",
          "forecasts": {"macbook": "weather/metal-slug-x-weather/forecast-macbook.json"}
        },
        {
          "id": "game-world",
          "title": "Игровой мир",
          "current_url": "weather/metal-slug-x-weather/sources/game-world/current.json",
          "forecasts": {"macbook": "weather/metal-slug-x-weather/sources/game-world/forecast-macbook.json"}
        }
      ],
      "availability": {
        "macbook": {"autumn": {"ready": 52, "total": 52}}
      }
    }
  ],
  "downloads": []
}
```

`collection.current_url` — адрес реального источника для совместимости. Для выбранного источника использовать **`collection.sources[].current_url` и `forecasts[D]`**. Отсутствующий в `sources` источник не предлагать пользователю.

Ключи `formats` динамические. Частые варианты: `macbook`, `display`, `phone`, но допустимы другие. Существование `macbook` не гарантирует наличие `display` или `phone`. Размеры брать из ответа, а не из имени формата. Выбор подходящего соотношения сторон, способ кадрирования и выбор монитора — задача приложения.

`ready_states` — число состояний, для которых готов хотя бы один формат; оно не гарантирует готовность выбранного устройства. `availability[D][season]` содержит счётчики по сезону и формату и может быть пустым у старых контрактов. Готовность текущего кадра определяют прогноз и `format_status`.

## 5. Текущее состояние `current.json`

Состояние зафиксировано на момент последнего серверного обновления. После границы интервала текущее изображение нужно определять по прогнозу.

| Поле | Тип / наличие | Смысл |
| --- | --- | --- |
| `schema`, `type` | `1`, `"weather"` | Тип документа |
| `collection_id`, `title` | строки | ID и название оформления |
| `source_id` | `"real"` / `"game-world"` | Источник |
| `world_id` | строка / `null` | Активная игра; `null` также возможен в ручном статическом режиме мира |
| `source` | объект / `null` | Название мира и сведения о происхождении погоды |
| `formats` | объект | Описания всех обнаруженных форматов |
| `package_versions` | объект | Независимые версии ZIP по ключу устройства |
| `location` | объект | `name`, `latitude`, `longitude`, `timezone` |
| `location_revision` | строка | Непрозрачный отпечаток координат, календаря и настроек климата |
| `timezone` | строка IANA | Например `Europe/Moscow` |
| `status` | строка | Общая готовность; см. раздел 9 |
| `reason` | строка / `null` | Машинная причина состояния |
| `files` | объект | Только готовые актуальные файлы: ключ — формат |
| `format_status` | объект, может отсутствовать | По формату: `{status, reason}` |
| `season`, `time_of_day`, `weather` | строки, могут отсутствовать; `weather` может быть `null` | Оси текущего состояния |
| `weather_code` | число / `null`, может отсутствовать | Код погоды |
| `state_id`, `state_title` | строка, могут отсутствовать; ID может быть `null` | ID состояния и подпись |
| `moon_phase` | строка, может отсутствовать | Фаза, использованная в текущем рисунке |
| `world_date` | `YYYY-MM-DD`, только для игрового мира при наличии данных | Дата по сохранённому календарю мира |
| `valid_from`, `valid_until` | дата-время, могут отсутствовать | Интервал текущего кадра |
| `forecast_valid_until` | дата-время, может отсутствовать | Конец срока всего действующего прогноза |
| `weather_fetched_at` | дата-время / `null` | Когда сервер получил/рассчитал погодные данные |
| `refresh_after` | дата-время | Когда уточнять JSON |
| `refresh_error` | `{at, message}` / `null` | Последний сбой обновления; действующий прогноз при этом может оставаться пригодным |
| `preview`, `preview_format` | объект и строка, могут отсутствовать | Малое превью и формат, из которого оно сделано |
| `last_successful_image` | объект / `null` | Сохранённые ранее успешные кадры |
| `delivery.direct_image.enabled` | boolean | Разрешены ли постоянные JPEG-адреса |

У `current.json` нет обязательных `generated_at`, `document_type` или `contract_version`. Не требовать их при разборе. В зависимости от ошибки возможны дополнительные диагностические поля `image_error`, `image_errors`, `preview_error`. Пользователю показывать понятный статус, а эти строки оставлять для диагностики.

Пример `source` активного игрового мира; название и платформа здесь условные:

```json
{
  "id": "game-world",
  "name": "Мир выбранной игры",
  "game": {"game_id": 12026, "title": "Выбранная игра", "platform": "Arcade"},
  "world_id": "ra-12026",
  "setting": "Городская окраина",
  "climate_model": "gpt-6-luna",
  "seed": 123456789,
  "date_offset_days": 0,
  "engine": "Fantasy Calendar",
  "revision": "fd33d2dd61de539cbc141de4c187d29a15578ef6",
  "adapter": "gregorian-daily/1",
  "url": "https://github.com/fantasycalendar/Fantasy-Calendar",
  "generated": true,
  "model_data": false,
  "cadence": "daily"
}
```

У `real` метаданные провайдера обычно содержат `id: "real"`, `name: "Open-Meteo"`, `url` и `model_data: true`. До получения погоды `source` может быть `null` или содержать только базовое имя игрового мира. Клиенту не нужно рассчитывать погоду из `seed`.

В API 1.7.0 **не публикуются температура, ветер, влажность, полный профиль климата Luna и рейтинг выбора игры**. Публичный контракт даёт состояние погоды и готовый рисунок. Нельзя рассчитывать на наличие полей `temperature` или `wind`.

## 6. Файл изображения

Полное изображение в `files[D]` или `interval.file`:

```json
{
  "url": "collections/metal-slug-x-weather/files/autumn-day-partly-cloudy-macbook.jpg",
  "format": "jpeg",
  "rendition": "macbook",
  "width": 3840,
  "height": 2400,
  "aspect": "16:10",
  "bytes": 1234567,
  "sha256": "abcdef0123456789abcdef0123456789abcdef0123456789abcdef0123456789",
  "cache_key": "0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef"
}
```

Значения хешей и размера в примере иллюстративные. `cache_key` — внутренний хеш задания рендера, он не является именем файла и не обязан совпадать с SHA-256 содержимого. Целостность проверять по `sha256` и `bytes`.

В `current.files[D]` дополнительно бывают:

- `state_id`, `state_title` — состояние именно этого файла;
- `image_url` — постоянный JPEG-адрес при включённом флаге;
- `preview` — превью для плеера, сохраняющее пропорции этого формата.

`interval.file` не обязан содержать эти добавления: состояние находится в самом интервале. `interval.image_url` — тот же путь, что `interval.file.url`; это не постоянный адрес `current-D.jpg`.

Превью имеет `url`, `format`, `width`, `height`, `bytes`, `sha256`; поля `rendition`, `aspect`, `cache_key` не обязательны. `interval.preview` — малая картинка, не более 640 пикселей по длинной стороне. `interval.player_preview` — увеличенное превью: вписано в 720×1560 для `phone` или в 1920×1200 для остальных форматов. Превью могут отсутствовать. Для системных обоев использовать полное `file`, а не превью.

Проверенные байты можно кешировать по SHA-256 и повторно использовать между источниками. Постоянный URL сам по себе не доказывает, что содержимое не изменилось. Перед установкой проверить размер, SHA-256 и размеры декодированного JPEG. Скачивать во временный файл и заменять локальный сохранённый файл после проверки. При ошибке сохранить ранее установленный кадр.

## 7. Прогноз `forecast-D.json`

Один документ на источник, оформление и формат. Горизонт при успешном обновлении — 24 часа от `generated_at`, не обязательно до местной полуночи. После ошибки сервера старый срок **не продлевается**.

| Поле | Значение |
| --- | --- |
| `schema` | `1` |
| `document_type` | `"weather-forecast"` |
| `collection_id`, `format` | Оформление и формат этого прогноза |
| `source_id`, `world_id` | Идентичность источника и активной игры |
| `contract_version` | Версия подготовленной коллекции |
| `package_version` | Версия ZIP этого устройства или `null`, если архив ещё отсутствует; может отсутствовать в старых документах |
| `location`, `location_revision`, `timezone` | Место и версия настроек |
| `generated_at` | Начало применимости всего прогноза |
| `valid_until` | Конец применимости всего прогноза |
| `refresh_after` | Когда уточнить JSON; не конец его применимости |
| `weather_fetched_at`, `source` | Метаданные погоды |
| `season_months` | Объект `winter/spring/summer/autumn` с массивами номеров месяцев |
| `astronomy` | Астрономические события и политика фаз Луны |
| `intervals` | Последовательность интервалов |

При отсутствии исходных данных сервер отдаёт укороченный документ с `status: "unavailable"`, `generated_at: null`, `valid_until: null`, `intervals: []`. `contract_version`, `timezone`, `refresh_after`, `weather_fetched_at`, `source`, `astronomy`, `season_months` в нём могут отсутствовать. У обычного действующего прогноза верхнего `status` может не быть — готовность находится в интервалах.

Сокращённый пример одного интервала:

```json
{
  "valid_from": "2026-10-28T12:00:00+03:00",
  "valid_until": "2026-10-28T16:58:28+03:00",
  "world_date": "2026-10-28",
  "season": "autumn",
  "time_of_day": "day",
  "weather": "partly-cloudy",
  "weather_code": 1,
  "state_id": "autumn-day-partly-cloudy",
  "moon_phase": "none",
  "status": "ready",
  "image_url": "collections/metal-slug-x-weather/files/autumn-day-partly-cloudy-macbook.jpg",
  "file": {
    "url": "collections/metal-slug-x-weather/files/autumn-day-partly-cloudy-macbook.jpg",
    "format": "jpeg",
    "rendition": "macbook",
    "width": 3840,
    "height": 2400,
    "aspect": "16:10",
    "bytes": 1234567,
    "sha256": "abcdef0123456789abcdef0123456789abcdef0123456789abcdef0123456789",
    "cache_key": "0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef"
  }
}
```

У неготового интервала есть `status`, `reason`, `image_url: null`; `file` и превью отсутствуют. Для неизвестного кода `weather` и `state_id` могут быть `null`.

Каждый интервал полуоткрытый: **`valid_from <= now < valid_until`**. В момент, равный `valid_until`, выбирать следующий интервал. Не округлять границы до часов или минут. Соседние отрезки одинакового состояния сервер объединяет; число интервалов не фиксировано.

`astronomy.engine` сейчас `astral/3.2`. В `astronomy.days["YYYY-MM-DD"]` передаются `dawn`, `sunrise`, `sunset`, `dusk`, `moon_phase`. В полярных условиях отдельные события равны `null`. Ещё есть `solar_depression` и `moon_policy`. Эти поля нужны для отображения и диагностики: выбирать кадр следует по готовым интервалам, не пересчитывая астрономию на клиенте.

Все временные метки содержат UTC-смещение. Сравнивать абсолютные моменты времени, а не строки. `world_date` — отдельная календарная дата. Верхний `manifest.timezone: "local"` может относиться к обычным коллекциям; для погоды использовать `current.timezone` / `forecast.timezone`.

## 8. Справочники

Сезоны: `winter`, `spring`, `summer`, `autumn`. Время суток: `dawn`, `day`, `dusk`, `night`.

| `weather` | Подпись | Коды в текущем отображении сервера |
| --- | --- | --- |
| `clear` | Ясно | 0 |
| `partly-cloudy` | Переменная облачность | 1, 2 |
| `overcast` | Пасмурно | 3 |
| `fog` | Туман | 45, 48 |
| `drizzle` | Морось | 51, 53, 55 |
| `rain` | Дождь | 61, 63, 80, 81 |
| `heavy-rain` | Сильный дождь | 65, 82 |
| `freezing-precipitation` | Ледяные осадки | 56, 57, 66, 67 |
| `snow` | Снег | 71, 73, 77, 85 |
| `heavy-snow` | Сильный снег | 75, 86 |
| `thunderstorm` | Гроза | 95 |
| `severe-thunderstorm` | Сильная гроза | 97 |
| `thunderstorm-hail` | Гроза с градом | 96, 99 |

Это таблица преобразования проекта, включая отдельное состояние 97; она не означает, что каждый провайдер выдаёт все перечисленные коды. Клиент использует готовые `weather` и `state_id`, а не повторяет таблицу для выбора JPEG.

`state_id` имеет вид `<season>-<time_of_day>-<weather>`. Пример: `autumn-night-severe-thunderstorm`. Не разбирать его простым `split('-')` на три части: группа погоды содержит дефисы. Для полей интерфейса использовать отдельные поля.

Возможные `moon_phase`: `none`, `new_moon`, `waxing_crescent`, `first_quarter`, `waxing_gibbous`, `full_moon`, `waning_gibbous`, `last_quarter`, `waning_crescent`. `none` означает, что лунный слой для этого рисунка не используется; это не синоним новолуния. JPEG уже содержит все необходимые слои.

## 9. Готовность и ошибки

HTTP 200 означает, что JSON прочитан, и не гарантирует готовность кадра.

| `status` | Действие клиента |
| --- | --- |
| `ready` | Для выбранного формата есть готовый файл; проверить и применить |
| `not_ready` | Текущее состояние известно, но соответствующего рисунка/варианта нет; сохранить последний кадр с пометкой |
| `unresolved_weather` | Код погоды не сопоставлен состоянию; сохранить последний кадр |
| `unavailable` | Пока нет погодных данных; показать недоступность либо сохранённый кадр |
| `stale` | Прогноз закончился; получить новый, сохранённый рисунок считать прежним |

`stale` применяется к общему текущему состоянию и локальной оценке прогноза; отдельный интервал обычно имеет `ready`, `not_ready` или `unresolved_weather`. Неизвестный статус считать неготовым.

Общий `current.status: "ready"` означает наличие **хотя бы одного** готового формата. Для конкретного устройства проверять выбранный интервал либо `format_status[D]` и `files[D]`. Неготовый `phone` не должен блокировать готовый `macbook`.

| `reason` | Смысл |
| --- | --- |
| `weather_unavailable` | Нет исходных погодных данных |
| `forecast_expired` | Закончился срок прогноза |
| `unknown_weather_code` | Нет сопоставления для кода |
| `state_not_in_collection` | В коллекции отсутствует состояние |
| `prototype_only` | Есть только прототип |
| `artwork_planned` | Рисунок ещё не готов |
| `prepared_variant_missing` | Нет готового варианта формата/фазы |
| `prepared_file_missing` | Подготовленный файл пропал либо изменился размер |
| `prepared_file_damaged` | Проверка файла при текущем обновлении не прошла |

Обрабатывать неизвестные причины без падения. HTTP 404, сетевые сбои и невалидный JSON — ошибки доставки; это не равнозначно `status: "not_ready"`.

`last_successful_image.files[D]` может содержать прежний успешный файл того же мира, даже когда текущий формат не готов. Брать `state_id` / `state_title` **из записи нужного файла**: общий `last_successful_image.title` может описывать более позднее обновление другого формата. `applied_at` — время серверного обновления сохранённых метаданных, а не время установки обоев клиентом и не отдельная дата каждого формата.

После окончания прогноза можно оставить уже установленный кадр, но нельзя выдавать его за подтверждённую текущую погоду. Нельзя молча подменять игровой мир реальной погодой или кадром другой игры.

## 10. Рабочий цикл приложения

1. Загрузить `manifest-v3.json`, проверить `schema: 3`, выбрать погодную коллекцию.
2. Дать выбрать источник из `sources` и подходящий формат из `formats`. Сохранить предпочтение пользователя. На сайте начальным источником служит `game-world`.
3. Загрузить `source.current_url`, проверить `schema`, `type`, `collection_id`, `source_id`.
4. Загрузить `source.forecasts[D]`. Сверить с текущим JSON `collection_id`, `source_id`, `world_id` и `location_revision`; проверить `format === D` и `schema: 1`.
5. Проверить `generated_at <= now < forecast.valid_until`. Найти **ровно один** интервал `valid_from <= now < valid_until`.
6. Если интервал готов, скачать его `file.url`, проверить целостность и применить. Если нужный `sha256` уже установлен и файл цел, повторная установка не нужна.
7. Сохранить прогноз, текущую идентичность и последний успешный файл. Заранее можно скачать следующий готовый кадр.
8. Поставить локальный таймер на ближайшую границу интервала. На границе выбрать следующий кадр из сохранённого прогноза, без обязательного HTTP-запроса.
9. Отдельно поставить обновление JSON на `refresh_after`. Если оно уже в прошлом или произошла ошибка, повторить примерно через 60 секунд, без непрерывного цикла запросов. Текущее серверное расписание обычно часовое, но интервал может быть изменён.
10. После сна, возобновления приложения, смены системного времени или возврата сети сразу пересчитать состояние по текущим часам и при необходимости обновить JSON. Не считать, что отложенный ОС таймер сработал вовремя.

Если обновить JSON не удалось, продолжать по **ранее проверенному совместимому прогнозу до его `valid_until`**. Прошедший `refresh_after` не делает такой прогноз просроченным. При этом сетевой сбой не разрешает продлить `valid_until`.

При смене пользователем оформления/источника/формата отменять либо игнорировать завершившиеся позже запросы прежнего выбора. Переключать системные обои только для актуального выбора. Это особенно важно при загрузке больших JPEG.

В `last_successful_image` сохраняются только файлы, которые ещё входят в текущий опубликованный набор и имеют прежний SHA-256. После удаления или замены такого файла запись может исчезнуть. Уже загруженные клиентом байты остаются в его локальном кеше.

### Кеш и смена мира

Рекомендуемый ключ прогнозов и логического последнего кадра:

```text
(collection_id, source_id, world_id, location_revision, device)
```

Байты проверенных JPEG можно хранить отдельно по `sha256` и повторно использовать. `location_revision` сравнивать только на равенство.

Если новый `current.world_id` отличается, сбросить прогноз и логический запасной кадр прежней игры. Если изменился `location_revision`, старый прогноз также не применять. API может отдавать ранее успешное изображение с прежней ревизией места: разрешено оставить его как прежний кадр с соответствующей пометкой, но не считать актуальным для нового климата.

При несовместимых текущем JSON и прогнозе возможно, что публикация произошла между двумя запросами. Не объединять их. Повторить чтение; до получения совместимой пары использовать только ранее проверенный комплект в его сроке действия и в прежней идентичности. Отдельный JSON записывается атомарно, общей транзакции на все HTTP-файлы нет.

### Минимальный выбор интервала на JavaScript

Это чистая функция проверки пары документов для одного формата. Она не скачивает JPEG, не проверяет его фактический SHA-256, не управляет таймерами и системными обоями.

```js
function selectWeatherFrame(current, forecast, device, now = Date.now()) {
  const id = current?.collection_id;
  if (current?.schema !== 1 || current.type !== 'weather' ||
      !/^[a-z0-9][a-z0-9-]{0,79}$/.test(id || '') ||
      !['real', 'game-world'].includes(current.source_id)) {
    return {status: 'unavailable', reason: 'invalid_current'};
  }
  const spec = current.formats?.[device];
  if (!spec || forecast?.schema !== 1 ||
      forecast.document_type !== 'weather-forecast' ||
      forecast.collection_id !== id || forecast.format !== device ||
      forecast.source_id !== current.source_id ||
      (forecast.world_id ?? null) !== (current.world_id ?? null) ||
      typeof current.location_revision !== 'string' ||
      forecast.location_revision !== current.location_revision) {
    return {status: 'unavailable', reason: 'incompatible_forecast'};
  }
  if (forecast.status === 'unavailable') return {status: 'unavailable'};
  if (!(Date.parse(forecast.generated_at) <= now &&
        now < Date.parse(forecast.valid_until))) {
    return {status: 'stale'};
  }
  const matches = (Array.isArray(forecast.intervals) ? forecast.intervals : [])
    .filter(row => Date.parse(row.valid_from) <= now && now < Date.parse(row.valid_until));
  if (matches.length !== 1) return {status: 'not_ready', reason: 'interval_missing_or_overlapping'};
  const row = matches[0];
  if (row.status !== 'ready') return {status: row.status, reason: row.reason};
  const file = row.file;
  const pathPattern = new RegExp('^collections/' + id + '/files/[a-z0-9-]+\\.jpg$');
  if (!file || !pathPattern.test(file.url) || file.format !== 'jpeg' ||
      file.rendition !== device || !/^[a-f0-9]{64}$/.test(file.sha256) ||
      !Number.isSafeInteger(file.bytes) || file.bytes <= 0 ||
      !Number.isSafeInteger(file.width) || file.width <= 0 ||
      !Number.isSafeInteger(file.height) || file.height <= 0 ||
      file.width !== spec.width || file.height !== spec.height) {
    return {status: 'not_ready', reason: 'invalid_file'};
  }
  return {status: 'ready', file, interval: row};
}
```

Далее адрес: `new URL(result.file.url, BASE)`. Применять только при `result.status === 'ready'` и после проверки скачанных байтов. Для нативных клиентов реализовать те же проверки средствами платформы.

## 11. ZIP и каталог подготовленных кадров

Для работы по сети достаточно текущего JSON и прогноза одного формата. `assets.json` и ZIP нужны для предварительной загрузки, офлайн-набора или просмотра всех состояний.

В корневом `manifest-v3.json.downloads` отбирать записи `collection === C`, `format === "zip"`, `rendition === D`. В записи есть `id`, `title`, `url`, `bytes`, `sha256`. Список находится на верхнем уровне каталога, а не обязательно внутри коллекции. Путь ZIP постоянный: `downloads/weather-C-D.zip`. Брать его из `url`; при обновлении по тому же адресу меняются `sha256`, `bytes` и `version`. Проверять новую версию по метаданным, а не по изменению имени. ZIP общий для обоих источников.

Архив содержит:

- `manifest.json`: `schema: 3`, `document_type: "weather-wallpaper-package"`, `type: "weather"`, `id`, `title`, `version`, `format` — ключ устройства, `ready_states`, `total_states`, `variants`;
- `weather-package.json`: `{schema: 1, type: "weather", format: D}`;
- `README.txt`;
- `files/*.jpg` — все готовые варианты этого устройства.

Каждая запись `variants` содержит `state_id`, `title`, `moon_phase` и поля полного изображения. В ней `url` переопределён на путь **внутри ZIP**, например `files/autumn-night-clear-full-moon-macbook-3840x2400.jpg`. Для офлайн-выбора сопоставлять `state_id` и `moon_phase` с интервалом прогноза и проверять целостность файла. Версию ZIP сопоставлять с `forecast.package_version` для выбранного устройства. `contract_version` относится ко всей коллекции и может измениться при добавлении рисунка для другого устройства, не затрагивая этот ZIP. Значение версии архива также доступно в записи скачивания `version` и в `collection.package_versions[D]`. Сам ZIP не содержит актуального прогноза и не позволяет предсказывать погоду после окончания сохранённого прогноза.

`assets.json` содержит `schema: 1`, `collection_id`, `type: "weather"`, `version`, `formats`, `ready_states`, `total_states`, `availability`, `states`. В `states[]` есть `id`, `title`, `status`, `moon_mode`, `variants[phase][device]`, а также доступные `previews` и `player_previews` той же вложенности. Здесь `file.url` остаётся публичным путём от базового адреса. В каталог попадают только состояния, готовые хотя бы в одном формате; отсутствие варианта другого устройства нормально.

## 12. Проверки перед выпуском клиента

- Переход на границе интервала с точностью до секунды без нового сетевого ответа.
- Отсутствие `phone`/`display` не мешает работать другому формату.
- Ошибка обновления при ещё действующем прогнозе и после его истечения.
- Смена `world_id`, `location_revision`, оформления и источника без применения запоздалого ответа.
- Неготовое состояние, неизвестный код, пустой прогноз и HTTP 404.
- Режим без постоянных JPEG-адресов.
- Повреждённый JPEG, несовпадение SHA-256, размера или разрешения.
- Возврат после сна, смены времени и часового пояса ОС.
- Использование подписи сохранённого файла, когда разные форматы обновлялись в разное время.

Неизвестные дополнительные JSON-поля игнорировать. Неизвестные значения статусов обрабатывать как неготовность. Не выбирать случайную доступную картинку в качестве текущей погоды.
