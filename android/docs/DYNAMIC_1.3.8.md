# Динамические обои · Android 1.3.8

Основа — Android 1.3.7 с локальным просмотрщиком. Пользователь ограничил реализацию получением готовой картинки с сервера: композиции слоёв на устройстве нет.

## Основание

Сверено с Gremlin_Build_Incremental_1.0.28_files.zip: SERVER_SPEC.md, gremlin_dynamic_wallpapers.py, gremlin_dynamic_build.py, gremlin_dynamic_publish.py и state.schema.json 0.2; художественная спецификация Dynamic_Wallpapers_Drawing_Spec_0.2.zip (текущая версия 1), включая LIFE_CLOCK.md и телефонный профиль 1440×3120. Сервер и художественные исходники этим обновлением не меняются. Производственные динамические обои на сервере пока отсутствуют; проверка выполнена на изолированных синтетических данных.

## Раздел и каталог

Новая кнопка раздела «Динамические обои» доступна наряду с обычными и погодными обоями. Читаются type=dynamic, formats и current_url; телефон определяется по вертикальным размерам, с предпочтением phone_1440x3120. Устройства и темы допускают подчёркивания согласно серверному контракту. Явно выбранный исчезнувший формат не подменяется настольным или другим.

Каталог допускает динамические коллекции без items и смешанный каталог. Они исключены из обычных коллекций и загрузчика погодных/обычных ZIP. Отсутствующие телефонные темы дают отдельное пустое состояние. Настройки экранов, пауза, отключение управления и сохранение черновиков продолжают действовать.

## Получение и установка

Пути относительно https://games.oopssre.ru/assets/arcade/views/:

1. Каталог: manifest-v3.json, запись type=dynamic.
2. Описание публикации: current_url коллекции, например dynamic/sunken-teahouse/current.json.
3. Запись нужного устройства из states[device], например dynamic/sunken-teahouse/devices/phone_1440x3120/current.json.
4. Готовый JPEG из image.url этой записи: dynamic/sunken-teahouse/devices/phone_1440x3120/current.jpg.

Это пути по спецификации, а не утверждение, что производственная тема уже опубликована. Адрес состояния сверяется с коллекцией/устройством, JPEG — с точным current.jpg. HTTP ограничен прежним HTTPS-хостом сайта. JSON использует существующую поддержку Brotli/gzip и .json.br.

Проверяются тип, версия 0.1/0.2, тема, устройство, время записи, размеры рецепта и изображения, форма active/layers, бытовой час 0–23/null и причина life для 0.2. Клиент читает нужные для показа поля; полный серверный движок правил и проверка канонического fingerprint всей записи не переносились. SHA-256, байты и фактическое разрешение JPEG проверяются обязательно.

Клиент не использует общий timestamp первого устройства как срок телефонного кадра. Проверяется format_status именно телефона и согласованность хеша между описанием публикации и записью телефона. При изменении стабильного URL между чтениями допускается не более двух попыток всей пары. Неподходящий, просроченный или ещё будущий опубликованный кадр не заменяет прежнюю пару.

Сначала готовится проверенный JPEG; только после этого атомарно сохраняется JSON текущей пары. Изменившаяся только запись JSON обновляет условия без новой передачи JPEG. Автосмена сравнивает хеш изображения; без изменения хеша повторная установка не нужна, кроме явного ручного применения. Перед установкой состояние проверяется ещё раз. На телефоне не вычисляются следующие состояния и не продвигается life-автомат.

Фоновые загрузки используют WorkManager с сетью и повтором с задержкой. Планировщик использует срок телефонной записи, проверяет публикацию не реже одного раза в час при разрешённой фоновой работе и держит резервную проверку. Ошибка оставляет последние установленные обои и видимую причину; для пустой/ошибочной публикации нет секундного цикла запросов. Реальное время исполнения фоновой задачи зависит от Android и прошивки.

## Просмотр и кеш

В просмотрщике доступны полученные JPEG и их сохранённые JSON. Подписи показывают сезон, время суток, укрупнённую группу погоды динамического контракта, Луну, игровые события и бытовой час. cloudy отображается как «Облачно», без подмены старой серверной таблицей погодных коллекций. Пропуск life-фазы остаётся решением сервера. Хранение JSON не означает, что клиент способен восстановить удалённый JPEG.

Согласованные условия очистки относятся только к кешу Android:

- Общее ограничение — 24 последних записи состояний и целевой объём 64 000 000 байт изображений. JPEG с одинаковым SHA-256 хранится один раз.
- Последний полученный кадр сохраняется даже при размере выше целевого объёма. Последние установленные приложением изображения двух экранов защищены; для них может оставаться дополнительная старая запись. Эти исключения могут превышать целевой лимит.
- Старая запись удаляется после успешного обновления, если больше не помещается в лимиты. Для одного защищённого JPEG не накапливается бесконечная история JSON.
- Изображения без оставшихся ссылок удаляются, только когда старше 5 минут. Задержка защищает параллельную загрузку другого экрана; до следующего обновления и во время задержки физический объём может быть выше ориентира.
- Вытесненная текущая запись не блокирует повторное получение темы. По возрасту календарных дней удаления нет. Без успешного нового обновления очистка не запускается.

Серверные theme ZIP, states.zip и история JSON не запрашиваются и не очищаются. Скачанный архив слоёв не требуется для работы этого режима.

## Слайд-шоу

Кнопка просмотрщика запускает полный экран и циклический показ доступных изображений с интервалом 2 секунды после готовности кадра. У динамической коллекции список сохранённых JPEG разворачивается от старых к новым; одинаковые JPEG уже объединены просмотрщиком, это последовательность сохранённых картинок, а не воспроизведение всех серверных записей автомата. В обычных коллекциях используется порядок списка.

Работают текущие фильтры. Для нуля или одного кадра кнопка отключена. При ошибке чтения показ останавливается с сообщением. Нажатие на изображение/Back возвращает управление и останавливает показ. Ручное листание, условия и фильтры также останавливают таймер. При onPause/onDestroy таймер снимается и флаг удержания экрана очищается; при возврате или пересоздании autoplay сам не возобновляется. Просмотр не загружает новые изображения и не устанавливает их как системные обои.

## Проверка

Новые проверки покрывают динамический и смешанный каталог, подчёркивания ID, отсутствие/исчезновение телефонного формата, тексты пустого раздела, отсутствие ZIP/городских контролов, передачу режима просмотрщику, успешное получение пары, отсутствие повторной загрузки JPEG, интервалы запросов, ошибки сети/хеша, гонку публикации, stale/not_ready, будущую/истёкшую запись, чужую тему/устройство/URL, версии и бытовой час, подписи, независимые профили/паузу, ограничение числа состояний, защиту установленных кадров, задержку удаления и вытеснение по объёму. Отдельные тесты с виртуальным временем проверяют интервал 2 секунды, цикл, остановку при возврате управления/уходе из Activity/ошибке, требование двух кадров и обратный порядок истории.

Результаты текущего запуска и число тестов: VALIDATION.md, docs/test-results, BUILD_1.3.8.log. Физическое устройство/системный эмулятор не запускались. Не заявляется проверка живой производственной темы, которой пока нет на сервере.
